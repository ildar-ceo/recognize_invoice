# AGENTS.md — инструкции для AI-агентов

Этот файл содержит инструкции для AI-агентов, работающих с данным репозиторием. Читайте его перед внесением изменений.

Пиши понятный и простой код старайся создавать только самое необходимое. Используй паттерны проектирования.

## О проекте

**Система распознавания электронных документов** (счета-фактуры, накладные и т.п.) с интеграцией в 1С.

- Веб-интерфейс: **FastAPI + Jinja2**
- Пользователь загружает картинку (скан/фото документа)
- Изображение распознаётся через **LLM** (модель определяет тип документа и вызывает типизированные tools)
- Результат (JSON) отправляется в **1С через OData API**
- В настройках хранятся: адрес 1С, логин/пароль; LLM — название модели, URL API, ключ/пароль

Подробные требования — в [`docs/task.md`](docs/task.md). Примеры документов для распознавания — в [`images/`](images/).

## Ключевые принципы

### Распознавание документов
1. Сначала определяется **тип документа** (отдельный лёгкий прогон LLM с minimal tools, напр. `set_doc_type`).
2. По типу подбирается **набор tools** (например, для ТОРГ-12: `set_header`, `add_row`, `set_total`, `set_signature`).
3. LLM повторно обрабатывает картинку с этим набором tools и «заполняет» документ.
4. Из вызовов tools собирается итоговый JSON.
5. Пользователь проверяет результат на странице предпросмотра и подтверждает.
6. Данные уходят в 1С через OData.

### Правила нормализации данных
- **Даты**: как цифровые (`16.12.2022`), так и прописью (`12 июня 2008`) → приводить к **ISO 8601** (`YYYY-MM-DD`).
- **Суммы**: формат `тенге` через запятую (`780,00`) → **Decimal**.
- **Суммы прописью** («Пятьдесят пять тысяч тенге 00 тиын») → сохранять и сверять с числовой суммой.
- **Закрытые/обезличенные поля** (серые прямоугольники на скане) → возвращать `null`, **не «угадывать»** данные.
- Текст с ошибками OCR исправлять только при явной уверенности, иначе сохранять как есть.

### Работа с LLM
- Пример кода распознавания (pydantic-ai, `BinaryContent`, capabilities/toolset) — в конце `docs/task.md`.
- Изображение передаётся как `BinaryContent(data=..., media_type='image/png')`.
- Инструменты (tools) должны быть строго типизированы (pydantic-схемы), результат — JSON по схеме из `docs/task.md`.

## Конвенции

- Язык проекта и документации — **русский**; идентификаторы в коде — английские (`snake_case` для функций/полей, `PascalCase` для классов).
- Схемы данных — **Pydantic v2**, валидация на входе и выходе.
- Асинхронность — `async/await` (FastAPI, OData-клиент, вызовы LLM).
- Конфигурация и секреты (адреса, пароли, API-ключи) — **не хардкодить**, хранить в настройках/переменных окружения; не коммитить `.env`.
- Новые типы документов оформлять как отдельный модуль: `doc_type` + набор tools + JSON-схема; документировать его в `docs/task.md`.
