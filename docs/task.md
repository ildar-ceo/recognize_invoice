# Требование: система распознавания документов с интеграцией в 1С

## Общее описание

Требование создать систему распознавания файлов, документов и интеграция с 1С. Это будет веб интерфейс на FastAPI + jinja шаблонизатор. На странице кнопка загрузить файл. Загружается картинка, она распознается через LLM. Затем информация из этой страницы отправляется в 1С через Api odata.

Также должна быть страница с настройками:
- адрес 1С, логин и пароль
- LLM: название модели, url api, пароль.

## Принцип распознавания

Будут распознаваться разные документы, поэтому первое нужно определить тип документа, затем для этого документа собрать список tools. Когда распознается картинка вызывается этот список tools. Например `add_row(название, код, товар, кол-во, цена)`. LLM должна прочитать картинку и вызывать эти tools. После этого вернуть результат в JSON.

## Разбор документов (по примерам из images/)

В примерах `images/image1.png` и `images/image2.png` — **товарная накладная**, унифицированная форма № ТОРГ-12 (утверждена постановлением Госкомстата России от 25.12.98 № 132), код формы по ОКУД **0330212**. Обе картинки — вариант «Страница 1».

### Шапка документа (структурированные поля)

- Организация-грузоотправитель (наименование, адрес, телефон, факс, банковские реквизиты)
- Структурное подразделение
- Грузополучатель (включая ИНН/КПП, банковские реквизиты, БИК, р/с)
- Адрес доставки
- Поставщик (реквизиты, банковские реквизиты)
- Плательщик (реквизиты, банковские реквизиты)
- Основание (например, «Договор создан из "1С:Розница 8"», номер и дата документа)
- Номер документа и дата составления (примеры: `ПР-90` от `12 июня 2008`, `1-52` от `16.11.2022`)
- Транспортная накладная (номер/дата), вид операции, номер страницы

### Таблица товарных позиций

Колонки (вариант формы из image1, 15 колонок):
1. № по порядку
2. Товар: наименование, характеристика, сорт, артикул
3. Код
4. Единица измерения (наименование)
5. Код по ОКЕИ
6. Вид упаковки
7. Количество в одном месте / мест, штук
8. Масса брутто
9. Количество (масса нетто)
10. Цена, руб. коп.
11. Сумма без учета НДС, руб. коп.
12. Ставка НДС, %
13. Сумма НДС, руб. коп.
14. Сумма с учетом НДС, руб. коп.

Расширенный вариант (image2, 18 колонок) дополнительно содержит:
- Штрихкод
- Страна происхождения
- Номер таможенной декларации

Примеры строк: `Конфеты "Ассорти" / Арт-3334455 / упак / 778`, `Уголь / УГ010 / шт / 796 / 4610014660129`.

### Итоговая часть (после таблицы)

- Итого по колонкам (количество, масса нетто, суммы)
- «Всего по накладной»
- «Товарная накладная имеет приложение на … записей/листах»
- Всего мест (прописью), масса груза нетто/брутто (прописью, напр. «Сто два кг»)
- Всего отпущено на сумму (прописью, напр. «Пятьдесят пять тысяч тенге 00 тиын»)
- По доверенности № / от, выданной
- Подписи: отпуск груза разрешил (Директор), главный (старший) бухгалтер, отпуск груза произвел, груз принял, груз получил грузополучатель (должность, подпись, расшифровка подписи)

### Особенности примеров

- `image1.png` — полностью заполненная накладная без НДС («Без НДС»), 7 строк товаров (конфеты, печенье, вафли), итог 44,000 / 5 240,00.
- `image2.png` — частично обезличенный документ (часть реквизитов перекрыта серыми прямоугольниками), 1 строка (Уголь), НДС 12%, итог 55 000,00. Распознавание должно уметь работать с неполными/закрытыми полями: возвращать `null`/пустое значение вместо «угадывания» данных.
- Встречаются как цифровые даты (`16.11.2022`), так и даты прописью (`12 июня 2008`) — нормализовать к единому формату ISO.
- Суммы имеют формат `руб.коп` через запятую (`780,00`) — нормализовать к Decimal.
- Встречаются суммы прописью («Пятьдесят пять тысяч тенге 00 тиын») — сохранять и сверять с числовой суммой.

## Предлагаемая схема JSON для ТОРГ-12

```json
{
  "doc_type": "torg12",
  "header": {
    "form_code": "0330212",
    "number": "ПР-90",
    "date": "2008-06-12",
    "consignor": "...",
    "consignee": "...",
    "supplier": "...",
    "payer": "...",
    "basis": "...",
    "total_in_words": "..."
  },
  "rows": [
    {
      "line_no": 1,
      "name": "Конфеты \"Ассорти\"",
      "code": "Арт-3334455",
      "barcode": null,
      "unit": "упак",
      "okei": "778",
      "qty": 5.0,
      "netto": 10.0,
      "price": 78.0,
      "sum_without_vat": 780.0,
      "vat_rate": null,
      "vat_sum": null,
      "sum_with_vat": 780.0
    }
  ],
  "totals": {
    "qty": 44.0,
    "netto": 70.0,
    "sum_without_vat": 5240.0,
    "sum_with_vat": 5240.0
  }
}
```

Соответствующие tools (вызываются LLM при распознавании):
- `set_header(field, value)` — поля шапки
- `add_row(name, code, unit, qty, price, ...)` — строка таблицы
- `set_total(field, value)` — итоги
- `set_signature(role, fio, position)` — подписи

## Этапы обработки

1. Загрузка изображения на странице.
2. Определение типа документа (LLM с trivial tools, например `set_doc_type`).
3. Выбор набора tools по типу документа и повторный прогон LLM с картинкой + этими tools.
4. Сборка JSON-результата из вызовов tools.
5. Предпросмотр распознанного на странице и подтверждение пользователем.
6. Отправка данных в 1С через OData API (адрес, логин, пароль из настроек).

## Пример загрузки картинки в LLM

```python
from pydantic_ai import Agent, ImageUrl, RunContext
from pydantic_ai.capabilities import AbstractCapability


class Recognize():

    def __init__(self):
        self.lines = []

    def add(self, name, value):
        self.lines.append({
            "name": name,
            "value": value,
        })


def tool_example(ctx: RunContext, name: str, value: str):
    ctx.deps.add(name, value)
    return "Message"


class Parser(AbstractCapability):

    def get_toolset():
        return FunctionToolset(tools=[tool_example])


def build_agent(name, capabilities):
    agent = Agent(
        name,
        capabilities=capabilities
    )
    return agent


async def run(agent, image):
```
